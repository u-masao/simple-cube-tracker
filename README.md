# Speed Cube Tracker

GAN スマートキューブ（**GAN i4 / i3 系**など）の **操作（モーション）と回転（姿勢）** を、タイムスタンプ付きで記録するブラウザ専用ツールです。
出力は時系列のテキストなので、そのまま **Gemini や Claude などの LLM に貼り付けて** 解析・評価してもらう用途を想定しています（API 連携はありません）。

- **ブラウザだけで完結** — 外部サーバー・CDN・API を一切使いません。依存ライブラリは `vendor/` に同梱しています。
- **接続は Bluetooth**（Web Bluetooth API）。
- 入力操作は **接続 / 切断 / ログクリア**。出力は **ログ表示 / ダウンロード / コピー**。

## 対応環境

| OS | ブラウザ | 対応 |
|----|----------|------|
| Android | Chrome | ✅ |
| Windows | Chrome / Edge | ✅ |
| macOS | Chrome / Edge | ✅（参考） |
| iOS | Safari / Chrome | ❌（Web Bluetooth 非対応） |

> Web Bluetooth は **HTTPS（または localhost）** でのみ動作します。GitHub Pages で公開すればこの条件を満たします。`file://` で直接開くと Bluetooth は使えません。

## 使い方

1. ページを HTTPS で開く（GitHub Pages など）。
2. キューブを少し回して起こしておく。
3. **接続** を押し、デバイス選択ダイアログでキューブを選ぶ。
4. キューブを操作すると、ログに時系列で記録されていく。
5. **コピー** または **ダウンロード** してログを取得し、LLM に貼り付ける。

### MAC アドレスについて

GAN キューブの通信は MAC アドレスに基づく暗号化を使います。多くの端末では広告パケットから自動取得しますが、取得できない場合は入力ダイアログが表示されます。

- Android の **Cube Station** アプリの端末情報、または **nRF Connect** などで確認できます。
- 一度入力すると端末名ごとにブラウザへ保存され、次回以降は自動で使われます。
- 保存した値は画面下部の「保存した MAC アドレスを消去」でクリアできます。

## 出力フォーマット

各行は次の形式です（先頭に `#` のヘッダー行が付きます）。

```
<接続からの秒>  <時刻>  <種別>  <詳細>
```

| 種別 | 意味 | 詳細の例 |
|------|------|----------|
| `MOVE` | 面回転の操作 | `R   serial=12 cubeT=1800ms` |
| `SLICE` | スライス手（M/E/S。実機状態から推定） | `M2   （スライス手: 実機状態から推定）` |
| `ROT` | キューブ全体の姿勢 | `q=(x, y, z, w) euler=(roll, pitch, yaw)deg w=0.66rad/s` |
| `FACELETS` | キューブの面の状態（Kociemba 表記 54 文字） | `UUUUUUUUURRR...` |
| `BATTERY` | 電池残量 | `87%` |
| `HARDWARE` | 機器情報 | `name=GAN i3 sw=... gyro=yes` |
| `SCRAMBLE` | 提示したスクランブル／適用完了 | `R U' F2 L D ...` |
| `MISSED` | BLE レベルで取りこぼした手（serial の飛び） | `2手を取りこぼし（serial 3 → 6）` |
| `SYNC` | 実機状態への再同期（下記参照） | `実機状態に再同期（スライス手/高速操作の可能性・差分16ステッカー）` |

- `ROT` のクォータニオンは `(x, y, z, w)`、オイラー角の面順は `U, R, F, D, L, B`。
- `MISSED`（serial の飛び）は本当の取りこぼしです。`SYNC` は取りこぼしではなく、下記のスライス手などによる状態差を実機状態（FACELETS）に合わせ直したものです。

### スライス手（M/E/S）の推定について

GAN キューブはコーナー／エッジの状態だけを送信し、**スライス手（M/E/S）や持ち替え（x/y/z）は MOVE として報告しません**。そのため、スライス手を使うと記録した面手だけでは実機の状態と食い違います。本ツールは、実機が報告する状態（FACELETS）の差分を解析し、**単一のスライス手で説明できる場合は `SLICE` として推定記録**します（直近の面手の間に挟まったスライスも位置を探索して復元）。

- 推定は実機状態と 54 ステッカー完全一致した場合のみ行うため、誤検出はまず起きません。説明できない差分は `SYNC` として実機状態に合わせ直します。
- なお持ち替え（x/y/z）はピースの相対位置を変えないため FACELETS に現れず、記録にも影響しません。
- この機能は「スライス手（M/E/S）を推定して記録」オプションで ON/OFF できます（既定 ON）。

> **GAN キューブのスライス報告について（既知の制約）**
> GAN キューブはコーナー／エッジのみを送信し、スライス手は**コア（中心）基準で外 2 層が逆回転したもの**として、`R L'` のような**外 2 層ペア**で報告します。さらに**高速スライス連打中は 1 手ごとの MOVE 列が実機状態を正確に再構成できない**ことがあります（ファームウェア側の制約）。このため、スライス中心の速い解きでは単一スライス推定が効かず `SYNC` が増えることがあります。いずれの場合も **FACELETS（全状態）が正**で、`MISSED`（serial の飛び）が出ていなければ手は失われていません。

### スクランブル提示

「スクランブル」パネルの **生成** で、WCA 風のランダムスクランブル（既定 20 手、同一面連続・同一軸 3 連続を回避）を表示します。

- **コピー** でスクランブル文字列を取得でき、出力ログの先頭にも `# スクランブル:` として含まれます（どのスクランブルの解きか LLM が把握できます）。
- 接続中は、**実機の状態**に基づいて進捗を表示します（適用済みを淡色・現在の手を強調・「次: ◯」を表示）。**ダブル手（例 `U2`）の1回転目も正しく扱い**（「あと1回転」）、打ち間違えた場合は「手順から外れています」と表示します。戻せば進捗も戻り、最終的に目標状態へ到達すれば完了（冪等）。
- **解除** ボタンでいつでもスクランブル追従をやめ、フリー記録に戻れます。
- 画面の「詳細（姿勢・検出）」「記録オプション」「使い方・メモ」は折りたたみ式です（既定は閉じた状態）。

### 記録オプション

- **回転（ジャイロ）を記録** … 姿勢ログの ON/OFF。
- **記録間隔 (ms)** … 回転ログの間引き間隔（`0` で全サンプル記録）。既定 250ms。
- **キューブ状態（FACELETS）を記録**。
- **整合チェック** … 記録した手順をシミュレートし、キューブが報告する実際の状態と照合して取りこぼし/誤記録を検出。
- **自動スクロール** / **画面を常にオンにする**（Wake Lock）。

## GitHub Pages で公開する

このリポジトリはそのまま静的サイトとして公開できます。

1. GitHub の **Settings → Pages** を開く。
2. **Build and deployment** の Source を **Deploy from a branch** にする。
3. Branch を公開したいブランチ（例: `main`）／フォルダ `/ (root)` に設定して保存。
4. 数十秒後に `https://<ユーザー名>.github.io/<リポジトリ名>/` で公開されます。

> `.nojekyll` を含めているため、Jekyll による加工なしでそのまま配信されます。

## ディレクトリ構成

```
index.html        … 画面
style.css         … スタイル
app.js            … アプリ本体（ES Module）
vendor/           … 同梱ライブラリ（外部アクセス不要）
  gan-web-bluetooth.js   GANキューブ通信（v3.0.2）
  rxjs.js / aes-js.js / tslib.js  依存
.nojekyll
```

開発用に `index.html?debug=1` を開くと、キューブなしで擬似イベントを流せるデバッグフック（`window.__sct`）が有効になります（通常動作には影響しません）。
